# ACS Email Setup Guide

## Prerequisites

- Azure subscription with Contributor access
- Bicep deployed from `src/BE/infrastructure/main.bicep`

## Overview

The API sends two types of emails via Azure Communication Services:

| Type | Endpoint | When |
|------|----------|------|
| Invite email | `POST /api/users/invite` | Admin invites a new user |
| One-time code | `POST /api/auth/send-code` | User requests login code |

Both use `AcsEmailService`, authenticated via the shared user-assigned managed identity.

---

## What the Bicep Provisions

The Bicep at `src/BE/infrastructure/main.bicep` creates three resources for email:

### 1. ACS Communication Service

```bicep
resource communicationService 'Microsoft.Communication/communicationServices@2023-04-01' = {
  name: 'acs-<company>-<env>'
  location: 'global'
  identity: { type: 'UserAssigned' ... }
  properties: { dataLocation: 'Europe' }
}
```

This is the main ACS resource. The `ACS_ENDPOINT` output resolves to `https://<acs-name>.azurecomm.net`.

### 2. Email Communication Service

```bicep
resource emailService 'Microsoft.Communication/emailServices@2023-04-01' = {
  name: 'email-<company>-<env>'
  location: 'global'
  properties: { dataLocation: 'Europe' }
}
```

Required to send emails. Separate from the main ACS resource.

### 3. Email Domain (Azure-Managed)

```bicep
resource emailDomain 'Microsoft.Communication/emailServices/domains@2023-04-01' = {
  name: 'AzureManagedDomain'
  parent: emailService
  location: 'global'
  properties: { domainManagement: 'AzureManaged' }
}
```

Auto-generates a domain like `alz-example-a1b2c3d4.azurecomm.net`. The `ACS_SENDER_ADDRESS` output shows the full sender address: `DoNotReply@<auto-generated-domain>.azurecomm.net`.

**No DNS changes needed** — Azure owns the domain.

---

## Step 1: Link the Domain to the ACS Resource

After deploying Bicep, connect the Email Communication Service domain to the ACS resource:

1. Go to **Azure Portal** → ACS resource (`acs-<company>-<env>`)
2. Navigate to **Email** → **Connected domains**
3. Click **Add domain** and select the Email Communication Service (`email-<company>-<env>`)
4. The Azure-managed domain appears — select it and confirm

Without this step, the ACS SDK cannot send emails through the domain.

---

## Step 2: Configure Sender Address

After deployment, get the `ACS_SENDER_ADDRESS` from the Bicep output. It will look like:

```
ACS_SENDER_ADDRESS = DoNotReply@alz-example-a1b2c3d4.azurecomm.net
```

Set it in **Azure App Configuration** (preferred for deployed environments):

| Key | Value |
|-----|-------|
| `Acs:Endpoint` | `https://acs-<company>-<env>.azurecomm.net` (from `ACS_ENDPOINT` output) |
| `Acs:SenderAddress` | `DoNotReply@<auto-generated-domain>.azurecomm.net` (from `ACS_SENDER_ADDRESS` output) |

For local development, use `appsettings.Development.json` or environment variables:

```json
{
  "Acs": {
    "Endpoint": "https://acs-<company>-<env>.azurecomm.net",
    "SenderAddress": "DoNotReply@alz-example-a1b2c3d4.azurecomm.net"
  }
}
```

The `AcsEmailService` reads config in this order:
1. `Acs:Endpoint` + `Acs:SenderAddress` from IConfiguration
2. `ACS_ENDPOINT` environment variable (fallback for endpoint only)

## Step 3: Deploy and Test

### Smoke test

```bash
curl -X POST http://localhost:5262/api/users/invite \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{
    "organizationId": "<org-id>",
    "emails": ["test@example.com"],
    "inviteBaseUrl": "http://localhost:5173/invite",
    "role": "User"
  }'
```

Check the API logs for:
```
Invite email sent to test@example.com. Status: Queued
```

---

## Step 4: Monitor

- **Email delivery status**: ACS resource → Email → "Sent" tab
- **API logs**: Application Insights → Search for `SendInviteEmailAsync` or `SendOtcEmailAsync`
- **Bounces**: ACS shows delivery failures in the "Sent" tab with error codes

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| `Invalid sender address` | Domain not linked to ACS resource | Step 1: Add domain in ACS → Email → Connected domains |
| `Unauthorized` | Managed identity lacks access | Verify identity has `Contributor` on ACS resource |
| `DataLocation mismatch` | ACS data location != Email Service data location | Both must be `Europe` |
| Emails not arriving | Check spam or sender not linked | Verify ACS_SENDER_ADDRESS matches the linked domain |
| `ACS_ENDPOINT` vs sender domain mismatch | The endpoint and sender domain are from different resources | The endpoint is from the ACS resource; the sender domain is from the Email Communication Service — this is correct |
