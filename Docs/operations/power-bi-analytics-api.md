# Power BI analytics API

**Linear:** WOR-542

## Purpose

The Workslip analytics report reads production analytics through the Workslip HTTPS API rather than connecting directly to Azure SQL.

Workslip now exposes two Admin-only Power BI surfaces with separate data boundaries:

- `/app/overblik` keeps the lightweight Workslip-native management analytics derived from the Power BI analytics contract.
- `/app/timer` can embed the configured authenticated Power BI report for interactive time analytics and keeps a direct Power BI fallback link.

Neither surface is available to non-Admin users.

## Production report source

Base URL:

`https://app.mrsoftware.dk`

Endpoint used by the PBIP semantic model:

`GET /api/worksheets/all/report/power-bi/data?historyMonths=24`

The endpoint is Admin-only and tenant-scoped from the authenticated Workslip user context. Power BI does not send or choose an organization id.

Response collections:

- `employees`
- `workHours`
- `jobs`
- `customers`

Metadata:

- `schemaVersion`
- `generatedAtUtc`
- `historyMonths`

## Power BI connection

The semantic model uses one shared `AnalyticsApi` Power Query expression and reuses the JSON response for all API-backed tables.

```powerquery
Json.Document(
    Web.Contents(
        #"ApiBaseUrl",
        [
            RelativePath = "api/worksheets/all/report/power-bi/data",
            Query = [historyMonths = Text.From(#"HistoryMonths")],
            Headers = [Accept = "application/json"]
        ]
    )
)
```

Parameters:

- `ApiBaseUrl = "https://app.mrsoftware.dk"`
- `HistoryMonths = 24`

Do not add `Sql.Database` or `Value.NativeQuery` to the report. No SQL credentials, API keys, bearer tokens, or passwords may be hardcoded in the PBIP project.

## Workslip placement contract

### Admin Overview

The circular **Sagsfordeling** chart on `/app/overblik` is rendered only for the exact `Admin` frontend role.

The chart does not download the full analytics payload. It reads a dedicated, tenant-scoped summary endpoint:

`GET /api/power-bi/overview/job-status`

The summary returns only:

- total jobs
- Draft count
- InReview count
- Approved count
- Rejected count
- other/unknown status count
- generated timestamp

The summary endpoint requires the backend `RequireAdmin` policy and derives the organization from the authenticated user context. There is no organization id route/query input.

### Admin Timer

The Admin Timer page `/app/timer` keeps its CSV/PDF worksheet controls and additionally renders a Power BI report section.

The frontend reads:

`GET /api/worksheets/all/report/power-bi`

The endpoint requires `RequireAdmin` and returns only a validated authenticated Power BI Service URL plus a derived secure embed URL:

```json
{
  "url": "https://app.powerbi.com/groups/.../reports/...",
  "embedUrl": "https://app.powerbi.com/reportEmbed?...&autoAuth=true"
}
```

The backend accepts only HTTPS URLs on the exact `app.powerbi.com` host with valid report/workspace coordinates. `Publish to web` URLs, non-default ports, embedded credentials and unsupported report URLs are rejected. The Timer iframe therefore never uses a public publish token generated by Workslip.

If the report cannot be embedded, the UI keeps an explicit state and, when a valid normal report URL exists, the user can open it directly in Power BI. Power BI authentication, licensing and RLS remain enforced by Microsoft.

## Validation boundary

Static validation verifies PBIP/PBIR/TMDL structure and model references. A full production report refresh still requires the analytics API to be deployed and Power BI authentication to succeed.

Workslip acceptance additionally verifies:

1. Admin Overview renders the circular job-status chart.
2. non-Admin Overview does not render or request the Power BI summary.
3. Admin Timer renders the Power BI section and requests the Admin-only report configuration endpoint.
4. a configured authenticated report is converted to the secure `reportEmbed` URL and can be shown in the Timer iframe.
5. an unconfigured or unsupported report produces an explicit recoverable UI state instead of an unsafe embed.
6. all Power BI endpoints remain tenant-scoped or Admin-protected on the backend as applicable.
